# 无头浏览器功能验收文档（Agent + 无头浏览器）

> 对应阶段：Phase 24（TODO.md 第 1012 行起）｜ 架构依据：[docs/architecture/browser.md](docs/architecture/browser.md)
> 功能定位：**后加的适配层**——静态 `HtmlListSource` 抓不了 JS 渲染站点（列表由脚本生成，HTML 里是空壳），本功能用 Playwright/Chromium + 本项目自己的 ReAct 循环浏览任意公网站点，提供「/crawl 任意网站」与「/agent 浏览网页」两个入口。

## 1. 验收目的

验证该功能不止「能跑」，而是真正兑现它的立项理由：

1. **能适配奇奇怪怪的网站**——JS 渲染列表页、需要滚动/翻页才有内容的站点，能拿到静态抓取拿不到的候选与正文；
2. **安全红线不破**——只读、SSRF 拦截、导航守卫、预算限制，任何一条被绕过都算验收失败；
3. **不给老功能添乱**——关掉开关或没装 Chromium 时，系统与验收前完全一致。

## 2. 验收前提（环境就绪 checklist）

| # | 条件 | 确认方式 |
| --- | --- | --- |
| E1 | 依赖已装：`cd server && uv sync --extra browser && uv run playwright install chromium` | `uv run python -c "from playwright.sync_api import sync_playwright; print('ok')"` |
| E2 | 根目录 `.env` 有 `BROWSER_ENABLED=true`（注意 `start.sh` 不剥行内注释，值后面不要跟 `#` 注释），已重启 server | `curl http://localhost:8000/api/config/features` 返回 `browser_available: true` |
| E3 | 老库已补列：`cd database && bash init.sh`（幂等，补 `browse_url` / `browse_goal`） | 建浏览器任务不报错 |
| E4 | 前端已起：`cd web && pnpm dev` | 能打开 `/agent` 与 `/crawl` |

> ⚠️ 本仓库约定验收由**用户实机执行**（CLAUDE.md 硬规则 1：助手不构建、不运行）。本文档只做指标定义与判定标准，所有命令由验收人执行并记录证据。

## 3. 验收指标

优先级说明：**P0 = 阻断项**（任何一条不过即验收不通过）；**P1 = 重要项**（允许 ≤1 条例外，须记录原因）；**P2 = 观察项**（只记录数据，不设硬门槛）。

### A. 功能完整性（两个入口真的能用）

| 编号 | 指标 | 通过标准（P0） | 验证方法 |
| --- | --- | --- | --- |
| A1 | 流水线入口端到端 | `/crawl` 选「任意网站（无头浏览器）」，入口 + 目标提交后：进度面板出现「浏览器：…」阶段 → 候选停在确认闸门 → 勾选确认 → 提取完成 → 成果库可见记录 | 走完一遍并截图成果库 |
| A2 | 对话入口端到端 | `/agent` 打开「浏览网页」，请求「打开某页面找 N 条内容给标题和链接」，助手气泡内渲染 step 列表（打开/快照/抽取），回答中的链接可点开 | 走完一遍并保留回答 |
| A3 | SSE `tool` 事件 | 浏览过程中前端逐步显示工具步骤（不是等最后一次性出现）；`token` / `tool` / `done` 顺序正确，无串行错乱 | 观察 + 必要时 `curl -N /api/chat/stream` 看原始事件 |
| A4 | 不可用前置报错 | `browser_enabled=true` 但 Chromium 缺失时，`/chat/stream` 在**流开始前**返回 400 且带安装说明；不是流中途报错 | 临时改配置复测 |
| A5 | 四镜像字段贯通 | `browse_url` / `browse_goal` 从建任务 → 任务详情 → 进度 → stage 2 重取，全程不丢 | 建任务后查库 `SELECT browse_url, browse_goal FROM crawl_task` |

### B. 适配效果（核心指标——这是功能存在的原因）

> 建议测试集：① `test_browser.py` 的本地 JS 假站点（离线基准）；② 1–2 个真实 JS 渲染站点（如 `https://www.news.cn/politics/`）；③ 1 个静态友好站点作对照。

| 编号 | 指标 | 通过标准 | 优先级 |
| --- | --- | --- | --- |
| B1 | **JS 渲染站适配成功率** | 测试集中每个 JS 渲染站点，发现循环至少收到 **≥1 个候选**（或正确判为「无目标内容」而非静默空跑）；成功率 = 适配成功站数 ÷ JS 渲染站数 ≥ **2/3** | P0 |
| B2 | **静态 vs 浏览器对照** | 同一 JS 渲染站点，静态抓取取不到正文/列表，浏览器入口取得到——证明适配层产生了增量价值 | P0（至少 1 组对照） |
| B3 | **候选有效率** | 确认闸门中人工勾选「通过」的候选占比 ≥ **50%**（模型捞回的链接大多数是目标内容） | P1 |
| B4 | **正文有效率** | 进入提取阶段的页面，正文预检通过率 ≥ **70%**；正文非空且明显不是导航/页脚拼接 | P1 |
| B5 | **字段完整率** | 提取入库记录中标题非空率 = 100%，发布日期非空率 ≥ **80%** | P1 |
| B6 | 发现循环效率 | 记录每任务：候选数、actions 数、stop reason；无「模型编造 URL」事件（候选只能来自 `browser_collect_links` 对真实快照的解析） | P2（只记录） |
| B7 | 二次抓取一致 | stage 2 的 `fetch_fulltext` 重开详情页后，标题/日期与 stage 1 预检一致（不因重渲染而漂移） | P1 |

### C. 安全红线（零容忍，全部 P0）

| 编号 | 指标 | 通过标准 | 验证方法 |
| --- | --- | --- | --- |
| C1 | SSRF 拦截 | `http://127.0.0.1:8000`、`http://192.168.x.x`、`http://169.254.169.254/latest`、非 http(s) 协议（`file:` 等）**全部被拒**，且给出明确原因文案 | 负例测试 ×4 |
| C2 | 只读不变量 | 对含 POST 表单的站点，提交被拦截，模型收到「只读模式不支持提交」类提示；页面内的非 GET 子请求被 abort | 负例测试 |
| C3 | 导航守卫无绕过 | 代码审计：仓库中不存在绕过 `guard.assert_navigation()` 直接 `page.goto` 的路径（子资源走 `route_handler`） | `grep -rn "page.goto" server/app/browser/` 逐一核对 |
| C4 | 预算硬上限 | 连续动作超过 `BROWSER_MAX_ACTIONS` 后工具返回预算耗尽，模型被迫收尾；**不存在** actions/pages/extracts 超限后仍继续执行的动作 | 设低预算复测（如临时改 `.env`） |
| C5 | fresh context | 两次连续运行（同会话）互不共享 cookie/storage；取消或 SSE 断连后 context 关闭（Chromium 进程数不随运行次数累积） | 任务管理器/进程列表观察 |
| C6 | 不可信内容包裹 | 工具结果中页面文本均在 `<untrusted_page_content>` 内；`prompts/chat_browser.md` / `browser_browse.md` 存在且被热读（改提示词不重启即生效） | 看 SSE 原始事件 + 改提示词复测 |

### D. 稳定性与资源

| 编号 | 指标 | 通过标准 | 优先级 |
| --- | --- | --- | --- |
| D1 | 并发排队 | 同时发起 > `BROWSER_MAX_SESSIONS` 个浏览器任务，多余任务**排队等待**而非报错失败 | 并发复测 |
| D2 | 超时兜底 | 单任务在 `BROWSER_TIMEOUT_SECONDS` 内必有终态（成功/预算尽/超时/失败），不死挂 | 造一个慢站点或卡住的页面 |
| D3 | 内存/进程不泄漏 | 连续完成 3 个浏览器任务后，Chromium 子进程数与内存回落到与任务前同一量级 | 复测前后对比 |
| D4 | 对话页高度锁定不回退 | `/agent` 在浏览多轮后仍锁定一屏（只有聊天区滚动，输入框钉底），无布局撑开 | 回归观察 |

### E. 降级与回归

| 编号 | 指标 | 通过标准（P0） | 验证方法 |
| --- | --- | --- | --- |
| E1 | 开关关闭降级 | `BROWSER_ENABLED=false` 重启后：来源下拉无浏览器项、对话无「浏览网页」开关，**其余功能照常** | 回归走一遍既有来源抓取 + 普通对话 |
| E2 | 定时任务隔离 | 定时任务选浏览器源被明确拒绝（「暂不支持」），不生成必失败任务 | API/UI 复测 |
| E3 | 冒烟测试全绿 | `uv run python scripts/test_browser.py` 全部 PASS，**不允许出现 skip**（skip = 环境未就绪 = 验收无效，回到 §2 前提） | 看测试输出计数 |
| E4 | 非浏览器路径零回归 | 已接入的常规来源（如 gov.cn MCP 链路）抓取、判别、提取结果与验收前一致 | 抽 1 个既有来源跑通 |

## 4. 判定规则

- **P0 全部通过** 且 **P1 例外 ≤1 条**（附原因）→ 验收通过，Phase 24 可标记「✅ 已完成」，在 `TODO.md` 与 `docs/progress/log.md` 记录证据。
- 任一 **P0 不通过** → 验收不通过，按缺陷修复后在受影响指标上复测（不要求全量重测，但要覆盖该指标及其关联项）。
- **E3 出现 skip 视同环境未就绪**，不得判定通过。
